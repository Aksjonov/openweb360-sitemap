Ты — сильный продуктовый дизайнер и редактор портфолио. Помоги мне написать полноценный кейс (case study) для моего портфолио по проекту редизайна сайта компании ООО «БАЛТТЕРМИНАЛСТРОЙ» (BTS). Ниже — все факты о проекте. Опирайся только на них. Если для сильного кейса не хватает данных (метрики, сроки, отзыв клиента), не выдумывай: сначала задай мне список уточняющих вопросов, а в тексте поставь заметные плейсхолдеры вида [УТОЧНИТЬ: …].

# 1. Контекст

- Клиент: ООО «БАЛТТЕРМИНАЛСТРОЙ» (БТС), Санкт-Петербург. С 2000 года разрабатывает, проектирует, проходит экспертизу и строит железобетонные купольные склады для хранения и перевалки сыпучих грузов (минеральные удобрения и т. п.). Проекты в России, СНГ, Европе и Азии. Флагманская фотография: терминал AS DBT в порту Мууга, Эстония — восемь белых куполов на берегу моря в сумерках.
- Услуги: предпроектные разработки, проектирование (разделы АР, КР, АС, КЖ, КМ), строительство (возведение, армирование, торкретирование).
- Аудитория сайта: B2B — заказчики терминалов и складских комплексов, инвесторы, проектные институты, в том числе иностранные. Решения принимаются долго, сайт должен вызывать доверие: портфолио, письма-рекомендации заказчиков, понятная технология, быстрый контакт.
- Старый сайт: btstroi.ru на Tilda. Двуязычный (RU/EN), разделы: Главная, О нас, Проекты (10 страниц проектов с галереями), Рекомендации (сканы писем заказчиков по годам), Технология (этапы строительства, видео), Контакты. Форма заявки работала через Tilda.

# 2. Проблемы исходного сайта (что было плохо)

- Зависимость от конструктора Tilda: нет контроля над кодом, производительностью и SEO.
- Нелогичная компоновка: например, на главной текст стоял слева, карточки проектов — посередине, а карта проектов внизу жила «сама по себе», не связанная с проектами.
- Устаревшая подача фото: фотографии проектов в карточке внутри подсвечиваемой карточки (вложенные рамки, свечение) — выглядело старомодно.
- Шрифт не соответствовал инженерно-строительному сегменту, размеры и отступы были случайными, анимации практически не работали.
- Мобильная версия — просто сжатый десктоп.
- SEO: на всех страницах стоял `lang="en"` даже у русской версии, не было канонических ссылок, hreflang, Open Graph-картинок и структурированных данных.

# 3. Что сделано и как (хронология, всё за один рабочий день — 17 октября 2026)

Инструменты: Lovable (AI-агент, React + Vite + TanStack Router + Tailwind CSS + shadcn/ui), Higgsfield (генерация изображения и видео), Claude (постановка задач, техзаданий и контроль качества), Playwright (автоматические скриншоты и проверки).

Этап 1. Перенос с Tilda на чистый React.
- Взял статический экспорт старого сайта и попросил воссоздать дизайн и функционал на React + Tailwind с аккуратной разбивкой на компоненты.
- Архитектура: все тексты и медиа в одном месте (`site.json`, собранный из экспорта Tilda, + словарь `i18n.ts`). Страницы — общие компоненты с параметром языка, тонкие маршруты RU (`/x`) и EN (`/en/x`). Это держит обе версии синхронными и сохраняет все старые URL (важно для SEO и ссылок).

Этап 2. Пиксель-в-пиксель сверка с оригиналом.
- Сравнил результат со скриншотами старого сайта, исправил расхождения: шрифт, круглая кнопка связи, карусель проектов, карта, лента писем, рекомендации по годам, чёрные секции преимуществ и контактов.
- Зачем: сначала получить честную «базу 1:1», чтобы улучшения были осознанными, а не случайными.

Этап 3. Редизайн («скопировали хорошо — теперь улучшаем»).
- Типографика: Golos Text + IBM Plex Sans — строгий инженерный гротеск, хорошая кириллица.
- Компоновка: заголовки и карточки на одной сетке, карта проектов связана с выбором проекта (карта перестала быть отдельным островом).
- Нумерованная структура секций (01 / О нас, 03 / Портфолио, 04 / Письма заказчиков) — читается как инженерная документация.
- Работающие анимации появления (Reveal) с учётом `prefers-reduced-motion`; hero-фото «ожило» (медленный наезд).

Этап 4. Анимированный hero: купола «строятся» на глазах.
- Задача: обязательно оставить фото терминала в hero, но сделать его живым и рассказывающим, чем занимается компания.
- Как: в Higgsfield по фото сгенерировал кадр «до» (модель GPT Image 2.5): та же съёмка, но вместо куполов — только круглые фундаменты с лежащей мембраной (ранняя стадия надувного купола). Затем модель FLUX 3 Video сделала видео с первым кадром «до» и последним кадром — оригинальным фото: мембраны надуваются и вырастают в купола, собираются галереи конвейеров. 8 секунд, 1080p, без звука, статичная камера.
- Поведение на сайте: видео проигрывается один раз и останавливается на финальном кадре (реальное фото готового терминала), дальше очень медленный Ken Burns-наезд. Кнопка в нижней панели hero — пауза/продолжение, после окончания — «построить заново». Пока видео грузится, показывается фото-постер (нет чёрной вспышки), плавный переход. При `prefers-reduced-motion` видео не грузится вовсе, только фото.
- Технически: ролик превысил лимит размера репозитория, поэтому лежит в хранилище ассетов Lovable; добавлена WebM-копия для совместимости браузеров. Написаны тесты на однократное проигрывание, перезапуск, паузу и reduced motion.
- Стоимость генерации: ~64,5 кредита Higgsfield.

Этап 5. Фотографии проектов.
- Убрал вложенные рамки и подсветку, укрупнил фото, сделал «архитектурную» раскладку и отдельный полноэкранный просмотрщик со стрелками. Письма-рекомендации (портретные документы) отделены от фотографий (ландшафтных) — у каждого типа своя подача.

Этап 6. Полный аудит качества — 32 страницы (RU + EN).
- Единая шкала отступов секций, общая сетка и левые края, единая типографическая шкала, `text-wrap: balance` для заголовков, одинаковые карточки и кнопки, аккуратный футер.
- Мобильная версия спроектирована отдельно, а не сжата: полноэкранное меню (Radix Sheet) с крупными тапами, телефоном и почтой; hero на всю высоту экрана (`svh`) с кадрированием, где купола остаются в кадре; свайп-галереи (Embla) со snap; компактная география вместо большой карты; карточки проектов — только фото, название, место/год; удобная форма (правильные типы полей, 16px — без зума на iOS); контекстная нижняя панель «Позвонить / Написать», которая появляется после hero и прячется у формы и футера. Нет горизонтального скролла на 360–1440 px.
- SEO и семантика: правильный `lang` у каждой страницы, уникальные title/description с ключевыми запросами («купольные склады», «железобетонные купола», «склады для сыпучих грузов», «терминалы для минеральных удобрений»; EN — «concrete dome storage», «bulk storage domes» и т. п.), canonical, hreflang-пары RU/EN, JSON-LD (Organization, BreadcrumbList, проекты), один h1 на страницу, alt-тексты, локализованная страница 404 в стиле сайта. Переключатель языка ведёт на ту же страницу в другой версии, а не на главную.
- Проверка: Playwright-скриншоты всех страниц на 390 / 768 / 1280 / 1440 px «до» и «после», 121 автоматическая проверка (навигация, языки, hero, карусели, диалоги, форма, клавиатура, reduced motion). Итог — два PDF: отчёт о качестве и сравнения «до/после» всех страниц.

# 4. Компромиссы, ограничения, от чего отказались (это важно — пиши честно)

- Видео — AI-генерация, а не реальная съёмка стройки. В кейсе это нужно прямо указать: финальный кадр — настоящее фото терминала, а процесс «возведения» — художественная визуализация. Реальные купола строятся не за секунды, и не все детали процесса технически буквальны.
- Отказался от зацикленного видео: бесконечный «строительный» луп отвлекает от текста и выглядит как скринсейвер. Выбрал один проигрыш + стоп на реальном фото.
- Отказался от точной копии старого сайта как финала: копия была только базой.
- Отказался от вложенных «карточек в карточках» и подсветки у фото — в пользу крупной фотографии.
- На мобильном осознанно убрана часть контента (большая карта, длинные тексты сокращены/свёрнуты) — ради скорости и фокуса на главном.
- Что стало хуже или сложнее (минусы):
  - Вес страницы вырос из-за видео в hero (митигировано: постер, preload, отключение при reduced motion, WebM).
  - Видео хранится во внешнем хранилище ассетов, а не в репозитории — ещё одна зависимость.
  - Форма заявки пока открывает почтовую программу посетителя (mailto) с готовым письмом, а не отправляет заявку напрямую — потенциальная потеря конверсии; прямая отправка — следующий шаг.
  - sitemap.xml, robots.txt и абсолютные ссылки на OG-картинки ждут подтверждения боевого домена; юридический адрес и соцсети в JSON-LD не заполнены — не было данных.
  - Автозапуск видео может блокироваться некоторыми браузерами/режимами энергосбережения — тогда пользователь видит первый кадр и кнопку «play».

# 5. Что нужно от тебя (структура кейса)

Напиши кейс на русском языке, объём ~1500–2500 слов, тон — уверенный, профессиональный, без воды и маркетинговых штампов. Структура:

1. Обложка: название кейса, подзаголовок в одну строку, теги (B2B, промышленность, редизайн, AI-видео, React), роль, сроки, инструменты.
2. Коротко (TL;DR): 3–5 пунктов — что было, что сделал, что получилось.
3. Клиент и контекст.
4. Проблема и цели (бизнес-цели + пользовательские задачи).
5. Аудитория и сценарии (кто приходит на сайт и зачем).
6. Процесс по этапам 1–6: что сделано → как сделано → почему именно так.
7. Ключевое решение: анимированный hero — отдельным крупным разделом (идея, генерация «до»-кадра, видео, поведение, доступность).
8. Мобильная версия как отдельный продукт.
9. SEO и техническое качество.
10. Что улучшилось / что ухудшилось — таблицей «было → стало» и отдельным честным списком минусов.
11. От чего отказались и почему.
12. Результаты: качественные факты из этого брифа + плейсхолдеры для метрик [УТОЧНИТЬ: скорость загрузки, конверсия, позиции, отзыв клиента].
13. Что бы сделал дальше (прямая отправка формы, домен и sitemap, реальная съёмка, аналитика).
14. Выводы и чему научился (работа с AI-агентами: постановка ТЗ, контроль качества, автоматические проверки).

# 6. Видео и иллюстрации — обязательно встроить в кейс

Для каждого места, где нужна картинка или видео, вставь блок-плейсхолдер такого вида:
`[МЕДИА: тип | что показать | подпись под иллюстрацией | зачем она здесь]`

Обязательный набор (используй все, распредели по разделам):
- ВИДЕО hero «купола возводятся» (8 с) — на обложке кейса или сразу после TL;DR, с автопроигрыванием без звука и подписью, что это AI-визуализация.
- Раскадровка видео: 3–4 кадра в ряд (пустые фундаменты → надуваются мембраны → купола растут → готовый терминал).
- Пара «до/после» hero: старый сайт на Tilda и новый hero.
- Полные скриншоты страниц (длинные, во всю высоту): Главная RU, Проекты, страница одного проекта, Технология, Рекомендации, Контакты — десктоп.
- Мобильные экраны 390 px, в ряд по 3–4: hero, открытое меню, свайп-галерея проекта, форма с нижней панелью «Позвонить / Написать».
- Отдельные элементы крупно: карточка проекта до и после; фото-просмотрщик; карта/география проектов; нумерованные заголовки секций (типографика Golos Text + IBM Plex Sans); кнопка паузы видео в нижней панели hero; страница 404.
- Сравнение «до/после» страниц из PDF-отчёта (сетка миниатюр 4 ширин: 390 / 768 / 1280 / 1440).
- Схема архитектуры: один источник контента (site.json + i18n) → общие компоненты → маршруты RU и EN.
- Схема пайплайна hero: фото → AI-кадр «до» (GPT Image 2.5) → AI-видео (FLUX 3 Video, кадры начала и конца) → сайт (постер, один проигрыш, Ken Burns, reduced motion).

# 7. Формат ответа

1. Сначала — список вопросов ко мне, без которых кейс будет слабее (не больше 10).
2. Затем — полный текст кейса в Markdown с плейсхолдерами медиа и [УТОЧНИТЬ].
3. В конце — чек-лист материалов, которые мне нужно снять/собрать (скриншоты, кадры видео, PDF), с точными размерами и названиями файлов.
4. Дополнительно: короткая версия кейса (150–200 слов) для карточки в портфолио и 3 варианта заголовка.
